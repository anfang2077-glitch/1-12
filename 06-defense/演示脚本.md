## 1 演示前置准备

### 1.1 环境检查（T-30 分钟）

```powershell
node -v                                   # 实测 v24.14.1，需 ≥ 20
npm -v                                    # 实测 11.11.0
Test-NetConnection 127.0.0.1 -Port 3000   # TcpTestSucceeded 应为 True（启动后）
Get-NetTCPConnection -LocalPort 3000 -ErrorAction SilentlyContinue   # 启动前应为空
```

- 关闭系统通知与输入法连续输入（避免弹窗遮挡界面）。
- 关闭浏览器自动更新；固定使用 Chrome 或 Edge，窗口缩放 100%。
- 投影分辨率建议 1920×1080；若为 1366×768，把浏览器缩放调到 90%。

5. 关闭录屏软件之外的所有闲聊窗口；开始本地录屏（见 3.3 预案）。

**时间**：40 秒（讲解约 100 字）。

### 段 2｜0:40–2:00　全局概览与新建账号（80 秒）

**操作步骤**

1. 在「全局概览」停留 5 秒，指一下七个计数卡片（用户总数 4、教师账号 1、学生账号 2、课程数 2、题库题目 16、考试场次 2、答卷记录 1）。
2. 点左侧「用户管理」，展示分页表格与角色筛选。
3. 点右上「新增用户」，填：用户名 `student03`、姓名 `演示学生`、角色「学生」、密码 `Stu@123`，提交。
4. 表格刷新后，在搜索框输入 `student03` 检索到新账号。
5. 点该行的「禁用」，在确认弹窗中点「禁用」；再点「启用」恢复（**只演示到确认弹窗出现即可，避免现场状态错乱**）。

**讲解词**

> 管理员负责账号与课程，是数据的最终责任人。概览页的七个计数是实时聚合出来的，不是写死的。用户管理支持按角色筛选和关键字检索，新建账号时用户名与角色创建后不可改，保证历史考试和成绩的归属不会漂移。这里还能重置密码、禁用账号——禁用后旧令牌立刻失效，因为鉴权中间件每次请求都会回查账号状态。

**预期界面反馈**

- 概览卡片数字与 1.5 节实测一致；「新增用户」弹窗表单带字段级校验提示。
- 提交成功出现绿色 toast「用户创建成功」，列表新增一行。
- 禁用确认弹窗文案含「禁用后「演示学生」将无法登录系统，确定继续吗？」。

**时间**：80 秒（讲解约 190 字）。

### 段 3｜2:00–3:30　题库、组卷页、指派与发布态（90 秒）

**操作步骤**

1. 切标签 2（teacher01），点「题库管理」，展示题目列表：题型筛选、难度、知识点列；鼠标移到「+ 新增题目」「批量导入」按钮上说明入口，**不点击**（省时且避免现场录入错字）。
2. 点「考试管理」，指顶部摘要「共 2 场考试 · 草稿 1 场 · 已发布 1 场」，说明「数据结构期中考试」已发布、另一场仍是草稿。
3. 打开草稿那场的「编辑」进入组卷页：展示左侧题库勾选、右侧已选 8 题与逐题分值、右上角「试卷总分 100」「及格线 60」；讲一句「及格线高于总分会被拦住」。
4. 返回列表，对「数据结构期中考试」点「指派」，弹窗里已勾选 2 名学生，直接点「保存指派（2 人）」，观察 toast。
5. 指状态列的「已发布」徽章，说明发布动作已在课前完成、发布后试卷内容锁定。

**讲解词**

> 教师是内容生产者。题库按课程隔离，只能看到本人课程的题，四种题型齐全，也支持 JSON 批量导入。组卷是手动选题加逐题改分，总分实时汇总，及格线不能超过总分。这场草稿我留着不动，已经发布的「数据结构期中考试」是课前发布的——发布要校验有题、总分大于 0、及格线不超过总分、开始时间早于结束时间，发布后试卷内容就锁定了，这里只演示发布后的状态和指派，避免打乱已有答卷。指派是覆盖式的，提交的名单替换原名单。

**预期界面反馈**

- 题库列表带分页与筛选；行内显示「知识点：…」或「未标注知识点」。
- 考试管理摘要「共 2 场考试 · 草稿 1 场 · 已发布 1 场」；状态列为「草稿」「已发布」徽章。
- 组卷页右上「试卷总分」「及格线」实时联动；已选题目行带「上移 / 下移 / 移除」。
- 指派弹窗提示「指派为**覆盖式**：提交的名单将替换该场考试现有名单（当前已指派 2 人）」；保存后 toast「已指派 2 名学生」。

**时间**：90 秒（约 200 字）。

> **口径说明**：本段**不现场点击「发布」**，只演示发布后的状态与发布校验规则，话术中如实说明「发布动作在课前完成」。若评委追问，回答「可以现场发布，但它会改变已有答卷的可见状态，演示中以不打扰数据为优先」，并按 `预测问答.md` Q11 展开四项校验。

> **风险点**：组卷页数据较多，若加载超过 2 秒直接返回列表，改为口头讲组卷（右侧总分汇总一句话带过）。

### 段 4｜3:30–5:20　学生开考、答题、刷新恢复（110 秒）

**操作步骤**

1. 切标签 3（student01），页面在「我的考试」，展示考试卡片：「数据结构期中考试」、考试时间窗、90 分钟、「总分 / 及格线 100 / 60」与「开始考试」按钮。
2. 点「开始考试」，在提示框中点确认（提示含「计时立即开始且不可暂停…答案会自动保存」）。
3. 进入答题页 `/student/exam/1`，指一下页面上的 8 道题、右上角倒计时与「答案将自动保存」状态。
4. 作答 1 道单选（点选项），等状态变为「✓ 已保存 HH:mm:ss」。
5. 作答 1 道多选、1 道判断题；故意在多选里只选一个选项（为后面判分 0 分做铺垫）。
6. 按 `F5` 刷新页面，等页面重新加载：**已答答案全部回填、倒计时继续、状态仍为已保存**。
7. 在简答题文本框输入一两句话（演示主观题作答）。

**讲解词**

> 学生只看到被指派的考试。点开始考试后，截止时间是服务端算出来的，取「开考时间加时长」和「考试结束时间」中较早的一个，前端只负责展示，改本地时钟没有用。每选一个选项就会保存：先本地即时反馈，防抖几百毫秒后按单题提交，数据库用唯一键做幂等写入，重复提交不会产生重复行。最关键的验证是这次刷新——答案全部回来了，倒计时接着走，没有重新计时。简答题不自动判分，交卷后进教师的待阅队列。

**预期界面反馈**

- 开考提示框文案：「点击「开始考试」后计时立即开始且不可暂停；答题过程自动保存，倒计时结束将自动交卷。」
- 答题页顶部「保存中…」→「✓ 已保存 17:xx:xx」；倒计时形如 `1:29:5x`（超过 1 小时按 `h:mm:ss` 显示）。
- 刷新后：URL 不变（`/student/exam/1`），已选项仍选中，保存状态恢复为已保存，剩余时间比刷新前少几秒（以服务端为准）。

**时间**：110 秒（约 260 字）。**风险点**：刷新后若出现「加载中」超过 3 秒，按 4.3 预案处理（不重复点击）。

### 段 5｜5:20–6:20　交卷与即时判分（60 秒）

**操作步骤**

1. 点右上「交卷」，在「确认交卷」弹窗中读一句提示，点「确认交卷」。
2. 等待跳转到成绩页 `/student/result/:attemptId`，指一下「客观题得分」与「主观题得分」（后者阅卷前为 0）。
3. 指一下其中一道题的「正确答案」与「解析」——说明这些字段交卷前不会出现在任何响应里。

**讲解词**

> 交卷在一个事务里完成判分：单选和判断精确匹配，多选必须集合完全相等，少选、错选、多选都是零分——这条口径写进了需求并用测试用例锁定，避免成绩争议。刚才多选我只选了一个，所以这道题 0 分。简答题不自动给分，先记 0 分进入待阅队列。交卷是幂等的，重复点或者超时自动交卷，都不会重复计分。

**预期界面反馈**

- 「确认交卷」弹窗文案：「交卷后不能修改答案，确定交卷吗？」
- 成绩页标题「成绩与解析」，显示「客观题得分」「主观题得分」两个数值，并提示「本卷仍有主观题待阅卷，当前总分为客观题得分，教师完成评分后总分会自动更新。」；下方显示「未及格 · 及格线 60 分」（视得分而定）。
- 逐题区域出现「正确答案」与「解析」；多选题该题得分 0。

**时间**：60 秒（约 150 字）。

### 段 6｜6:20–7:40　教师阅卷与总分重算（80 秒）

**操作步骤**

1. 切标签 2（teacher01），点「阅卷中心」，展示「待阅答卷 2 份」。
2. 打开李小明那份答卷的「阅卷详情」弹窗，指一下客观题区域「客观题已由系统自动判分，无需人工评分」。
3. 给两道简答题分别打 15 分、10 分，填一句评语，点「提交评分」。
4. 观察 toast 提示的总分与「待评简答」数量变化。

**讲解词**

> 待阅列表按「还有多少道简答题没评」统计，不是按答卷状态统计，所以一份卷评了一半仍然在列表里。阅卷只允许给简答题打分，客观题不允许人工改，否则自动判分的可复核性就没了。总分不是累加出来的，而是每次提交后重新求和，所以反复改分不会出现分数漂移。提交后状态变成已评分，学生就能看到评语。

**预期界面反馈**

- 阅卷中心描述文案：「待阅答卷 2 份 · 简答题需人工评分，提交后系统自动重算总分。」
- 弹窗标题「阅卷 · 李小明 · 数据结构期中考试」，客观题显示「客观题已由系统自动判分」。
- 提交成功 toast：「评分已保存，当前总分 xx 分」。

**时间**：80 秒（约 190 字）。

## 3 应急预案（三套，按发生概率排序）

### 3.1 预案一：后端未启动 / 已崩溃

| 项 | 内容 |
|---|---|
| **症状** | 登录页点「登 录」后提示「网络错误」或一直「登录中…」；浏览器控制台出现 `ERR_CONNECTION_REFUSED`；`/api/...` 请求全红。 |
| **判定（10 秒内）** | 看终端 A 是否有监听日志；`Test-NetConnection 127.0.0.1 -Port 3000` 为 False 即确认。 |
| **处置** | ① 终端 A 按 `Ctrl+C` 结束残留进程；② `cd code\server` 执行 `npm run start:memory`；③ 用 1.2 节登录自检命令确认返回 `code=0`；④ 浏览器刷新一次，重新登录。 |
| **耗时目标** | ≤ 60 秒；超时直接进兜底。 |
| **兜底** | 切到「PPT 第 6~9 页讲架构与流程」继续讲 2 分钟，同时后台重启；仍失败则播放本地录屏（见 3.3）。 |
| **话术** | 「后端进程刚被我不小心关掉了，正好借这个空档讲一下服务是怎么启动的——它读环境变量、装配仓储、监听 3000，一行命令就能起来。给我二十秒。」 |
| **恢复验证** | 登录成功 + 概览页七个计数正常，即视为恢复；**不要**在学生已开考后重启内存后端（答卷会丢），改用录屏补讲该段。 |

### 3.2 预案二：数据库异常 → 切换 memory 模式

| 项 | 内容 |
|---|---|
| **症状** | 页面提示「服务器内部错误」，响应体 `code=50001`；终端 A 日志出现 `ER_ACCESS_DENIED_ERROR`、`ECONNREFUSED 3306`、`ER_BAD_DB_ERROR` 等前缀；多数接口 500。 |
| **判定** | 确认是 MySQL 侧问题（连接/库/权限），而非代码异常；此时切内存模式最快。 |
| **处置** | ① 终端 A `Ctrl+C`；② 两种等价做法任选：`npm run start:memory`（推荐，无需改文件）；或复制 `.env.example` 为 `.env` 并把 `MYSQL_DRIVER=memory` 后 `npm start`；③ 前端无需改动（代理地址不变），刷新页面重新登录。 |
| **数据说明** | 内存模式与 MySQL 使用**同一份种子数据**（`db/seed-data.js`），用户、课程、题目、考试、待阅答卷形状一致，七步闭环完全可走；区别是数据不持久化，进程退出即重置。 |
| **话术** | 「数据库这会儿连不上，我切到内存仓储演示——它和 MySQL 实现同一套仓储接口，业务代码一行没改，这也正好说明双实现的价值：测试和演示都不依赖数据库。」 |
| **注意** | 切换后进程内数据回到种子状态，三个标签应刷新并**重新登录**（避免旧上下文残留）；先讲这句，避免观众以为系统崩溃。 |

### 3.3 预案三：网络断开 / 服务不可用 → 本地截图与录屏

| 项 | 内容 |
|---|---|
| **症状** | 页面白屏、请求长时间 pending、`net::ERR_INTERNET_DISCONNECTED`；或投影机断连导致无法操作。 |
| **前提** | 本系统前端与后端都在本机，**断开外网不影响演示**；真正需要兜底的是本机服务异常或投影故障。 |
| **处置（按顺序）** | ① 先判断是否只是外网断：本机演示无需外网，继续操作并说明「系统不依赖外网」；② 若本机服务异常且 60 秒内修不好，切到 PPT 第 10 页讲页面清单与路径；③ 播放提前录制的**本地录屏**（建议 3 分钟精简版，覆盖：开考 → 答题保存 → 刷新恢复 → 交卷判分 → 阅卷 → 统计）；④ 若无录屏，用提前截好的 6 张关键界面截图逐张讲（列表→答题→已保存→交卷→阅卷→统计）。 |
| **准备要求** | 录屏与截图在答辩前一天生成，存本机桌面与 U 盘各一份，文件名 `demo-fallback.mp4` / `shot-01..06.png`；**答辩当天早上试播一次**。 |
| **话术** | 「现场环境有点问题，我用提前录好的操作录屏把这半段过一下，数据和刚才讲的一致：这是开考、这是自动保存、这是刷新后的恢复、这是交卷判分、这是阅卷重算、这是统计。」 |
| **禁止** | 不要在现场反复刷新、反复点「交卷」、或打开控制台调试——会让评委误以为系统不稳定。 |
