## 3 测试策略

### 3.1 分层策略

| 层级 | 手段 | 范围 | 环境 |
|---|---|---|---|
| L1 单元/组件 | 既有 Jest 用例（`tests/*.test.js`，119 条） | 判分函数、校验工具、服务层规则 | Jest + 内存仓储 |
| L2 接口集成 | 新增 `tests/api.integration.test.js`（63 条） | 基线 §5 全部 36 个接口的正常流 + 异常流 | supertest + `createApp` 工厂 + 内存仓储 + 注入假时钟 |
| L3 业务规则 | 新增 `tests/business.rules.test.js`（35 条） | 判分边界、超时自动交卷、幂等、阅卷越界、统计口径 | 同上 |
| L4 前端构建 | `npm run build` + 产物体积核对 | 全量页面可编译、无未解析依赖 | Vite 5 生产构建 |
| L5 静态审查 | 关键字检索（`answer`/`analysis`/`password`/`mock`）、分层目录检查、源文件行数统计 | 答案保密、口令保密、无硬编码 mock、可维护性 | PowerShell 检索 |

### 3.2 设计方法

1. **契约驱动**：用例的前置/步骤/预期直接由基线 §5 的接口表与错误码派生，一条契约至少一条断言。
2. **等价类 + 边界值**：分页（`page=1`、`pageSize=100/101`）、分值（0、0.01、两位/三位小数、越界）、分数段边界（59.99/60/90/100）、时间边界（deadline−5s、deadline+5s）。
3. **状态迁移覆盖**：`draft → published`、`in_progress → submitted → graded`，覆盖非法迁移（已发布不可改、已交卷不可写、未交卷不可阅卷）。
4. **权限矩阵驱动**：按基线 §3 的三角色 × 八功能矩阵，每个「❌」格至少一条 403 断言，每个「本人」约束至少一条横向越权断言。
5. **缺陷反证**：对可疑实现先写「按需求应为」的断言，运行得到失败（红），确认缺陷后再修复并回归（绿），全过程保留输出。

### 3.3 测试数据策略

- 每个 `it` 通过 `createTestContext()` 建立**独立**内存仓储并从种子数据初始化，避免用例相互污染；令牌由真实登录接口获取，不用手工伪造（伪造令牌用例除外）。
- 种子数据（基线 §8）：4 个账号（admin/teacher01/student01/student02）、2 门课程、16 道题（四题型齐全）、2 场考试（1 场 published 且指派 2 人、1 场 draft）、1 份已交卷待阅答卷（50 分）。
- 时间：通过 `clock` 注入与 `ctx.advance(seconds)` 控制，避免 `sleep` 造成的非确定性；超时类用例不依赖真实等待。
- 统计类用例通过仓储直接构造「已交卷」样本（10 份、分数 55~100），用于锁定五段分布与及格率算法，构造方式在用例注释中说明。
