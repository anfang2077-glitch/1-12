# 需求追踪矩阵（Requirements Traceability Matrix）

> 文档编号：EXAM-RTM-001　版本：v1.0　编制：需求分析师（RA）　日期：2026-10-31　阶段：P1
> 依据：`01-requirements/需求规格说明书.md`（FR-01~FR-38、NFR-01~NFR-18）、`00-team/project-brief.md`（基线 §4 数据表、§5 接口契约、§6 代码结构）
> 用途：建立「需求 → 设计 → 接口/数据表 → 测试用例」的单向可验证链条，满足质量门禁 G1「≥20 条需求且全部可追踪到设计与测试」。

## 1 使用说明

### 1.1 列定义

| 列名 | 含义 | 填写规则 |
|---|---|---|
| 需求编号 | FR / NFR 编号 | 与需求规格说明书逐字一致，连续不跳号 |
| 需求名称 | 需求的简短名称 | 与需求规格说明书一致 |
| 优先级 | P0 / P1 / P2 | 见 SRS §8.1 |
| 设计章节 | 承接该需求的设计单元与章节 | 引用 `02-design/系统设计说明书.md`，格式为「D 码 §章节」（D 码见 §1.2） |
| 接口/数据表 | 实现该需求使用的接口路径与数据表 | **接口必须为基线 §5 的真实路径**（含 `:id` 占位符）；**表必须为基线 §4 的 8 张真实表名**；全局约束类需求另附代码构件路径（基线 §6） |
| 测试用例编号 | 验证该需求的主测试用例 | `TC-xx` 格式，一需求一主用例（1:1 锚定），由测试工程师（QA）对齐并扩展 |
| 状态 | 追踪状态 | 取值：已定义 / 已设计 / 已实现 / 已测试 / 已验收。RA 交付时全部为**已定义**，后续由对应角色推进 |

### 1.2 设计单元编码（D 码）与设计文档章节对照

| D 码 | 设计单元 | 设计文档章节 |
|---|---|---|
| D1 | 总体架构与分层 | 系统设计说明书 §3.1 |
| D2 | 部署与运行环境 | §3.2 |

| D13 | 关键场景时序图（登录/开考/自动保存/交卷判分/阅卷） | §6 |

> 说明：D 码为追踪矩阵的稳定锚点，不随设计文档章节号微调而失效。若系统架构师（SA）调整章节编号，只需更新本表，不影响 56 行追踪数据。

### 1.3 测试用例编号规则

- 采用「一需求一主用例」的 1:1 锚定：FR-01 → TC-01 … FR-38 → TC-38，NFR-01 → TC-39 … NFR-18 → TC-56。
- QA 若需细分场景，在主用例编号后追加序号（如 `TC-16-1`、`TC-16-2`），**主用例编号不变**，保证追踪链不断。
- 若某需求在测试阶段被判定不可测，须在 `00-team/协作日志.md` 提变更单，不得直接清空本列。
