## 一、调研目的与方法

调研回答三个问题：现有考试组织方式在哪些环节失效；同类系统已解决什么、还缺什么；本项目应取何种定位。方法为「文献研读 + 公开资料分析 + 场景推演」，不采集真实师生数据。

## 二、传统考试方式的五个失效点

一是**成本与周期**。命题至统计十余环节串行推进，周期以周计，临时调整几无可能，难以支撑高频过程性评价。二是**泄题风险集中于物理流转**。试卷多次交接，任一环节失守即整场失效，事后难以定位责任环节。三是**阅卷尺度不一**。客观题人工逐份比对，主观题由多位教师批阅，缺乏统一标定与评分痕迹。四是**数据反复转录**。登分、核分、及格率与分数段统计需人工二次录入，错误难以自查。五是**数据资产流失**。纸质答卷难检索、难长期保存，题目正确率与知识点薄弱项无法沉淀，教学改进缺少依据。

## 三、同类系统功能对比

| 对比维度 | 超星学习通（考试模块） | 雨课堂 | 学堂在线 | Moodle（Quiz） | Canvas LMS |
|---|---|---|---|---|---|
| 定位与规模 | 综合教学平台，面向全校/多校 | 课堂互动工具，侧重随堂测验 | 大规模开放在线课程平台 | 开源学习管理系统，可自建 | 商业 SaaS 学习管理系统 |
| 题型与题库 | 题型齐全，支持分类题库 | 以客观题为主 | 题型较全，含作业互评 | 题型齐全，题库分类细致 | 题型齐全，Item Bank 成熟 |
| 组卷方式 | 手动 + 随机抽题 | 随堂即时出题 | 手动组卷为主 | 手动 + 随机题组 | 手动 + 题库随机抽题 |
| 作答可靠性 | △ 依赖网络，恢复不稳定 | △ 以课堂实时性优先 | △ 考试非核心场景 | ✓ 逐步保存，进程可续 | ✓ 自动保存完善 |
| 计时权威性 | △ 客户端计时为主 | △ 弱化服务端校验 | △ 非核心能力 | △ 依赖服务端但配置复杂 | ✓ 服务端计时 |
| 自动判分（多选口径） | ✓ 支持部分分，可配置 | ✓ 客观题即时判分 | ✓ | ✓ 部分分规则可配置 | ✓ 规则可配置 |
| 主观题人工阅卷 | ✓ 在线批阅 | △ 以客观题为主 | ✓ 支持互评与教师评阅 | ✓ 支持评分量规 | ✓ 支持 Rubric |
| 统计深度 | ✓ 报表丰富，偏管理视角 | △ 课堂数据为主 | △ 学习行为统计为主 | ✓ 成绩簿细，需自行配置 | ✓ 学习分析能力强 |
| 部署与数据自主 | ✘ SaaS，数据在第三方 | ✘ SaaS | ✘ 平台托管 | ✓ 完全自建 | ✘ SaaS |
| 二次开发难度 | 高（闭源） | 高（闭源） | 高（闭源） | 中高（插件复杂、体量大） | 高（闭源，仅 API 扩展） |

**图例**：✓ 具备且较完善；△ 具备但受限、需额外配置或非核心场景；✘ 不具备。

**结论**：综合平台强在生态与报表，弱在严肃考试的流程管控与数据自主；开源系统强在可自建，弱在部署复杂度；课堂工具强在即时性，弱在纪律保障。**没有一款产品同时做到「闭环完整 + 轻量自建 + 口径透明 + 工程可验证」**，此即本项目切入点。

## 四、三点启示与本系统定位

第一，**机考的价值不只是省纸**，而是把计时、判分、统计转为可审计的确定性流程，故「服务端权威计时」应为核心需求。第二，**可靠性比功能数量更决定口碑**，同类系统最集中的抱怨是断线丢答案与倒计时不准，故自动保存与断线恢复须以可度量指标约束（落库 ≤ 3 秒、恢复偏差 ≤ 5 秒）。第三，**判分口径必须显式化**，多选「少选是否给分」若不在需求中写死必生争议，故明确「少选、错选、多选均不得分」并写入测试用例。

据此定位为：面向单门课程与单个教学班的**轻量级严肃考试系统**，以 React 18 前后端分离 + Node.js/Express 4 + MySQL 8.0 实现七步闭环；明确不实现摄像头监考、AI 判分、移动端与多租户，把能力边界写进论文「不足与展望」。
