## 3. 关键决策记录（Decision Log）

| 编号 | 决策 | 背景 | 结论 | 影响 |
|---|---|---|---|---|
| DG-01 | 接口总数定为 36 条 | 任务书写「40+」，基线逐表清点实为 36 | 以基线为准，不编造接口；契约、设计、代码、测试统一 36 | 全链路一致，避免契约漂移 |
| DG-02 | 数据访问不使用 ORM，改为 Repository 双实现 | 测试环境无 MySQL；统计需要多表聚合 | mysql2 参数化 SQL + 内存实现，`MYSQL_DRIVER=memory` 即可跑测试与演示 | 217 条测试无需数据库；覆盖率真实反映业务逻辑 |
| DG-03 | 计时以服务端 `deadline_at` 为唯一权威 | 客户端倒计时可被刷新/改钟绕过 | 开考时一次性计算入库，此后所有请求先判超时 | 论文创新点一；D-01 由此暴露并被修复 |
| DG-04 | 多选判分「少选/错选/多选一律 0 分」 | 各类平台口径不一，易起争议 | 写入需求、接口契约、测试用例三处锁定 | 成绩争议可复现 |
| DG-05 | 客观题 `accuracy` 与基线口径对齐 | QA 质疑实现为「平均得分/满分」 | 客观题全对才得分，故该式等价于「答对人数/作答人数」；简答为得分率 | 文档按此口径表述，不改代码 |
| DG-06 | 前端不引 UI 组件库 | 体积与可控性 | 自研 15 个组件 + 原生 CSS，gzip 100.40KB | 论文 5.3 节说明取舍 |
| DG-07 | 论文图由脚本绘制而非截图 | 无浏览器渲染环境，避免伪造界面 | Pillow 绘制 9 张示意图（架构/ER/时序/界面原型），标注为「示意图」 | 图源在 `tools/make_figures.py`，可复现 |

## 6. 端到端联调记录（PM 复核）

在 `MYSQL_DRIVER=memory` 下以 `POST /auth/login` 获取学生令牌，依次执行：

```
开考  POST /api/exams/1/attempts        → attemptId=2, deadline=2026-10-31 19:12:47
取卷  GET  /api/exams/1/paper           → 8 题，无 answer/analysis 字段
保存  PUT  /api/attempts/2/answers × 8  → 逐题 savedAt 返回
交卷  POST /api/attempts/2/submit        → total=20, objective=20, pending=2
成绩  GET  /api/attempts/2/result        → 20/100, items 8 条
阅卷  GET  /api/grading/pending         → 2 份待阅（含种子答卷）
阅卷  POST /api/grading/1                → 50+32=82，status=graded
统计  GET  /api/stats/exams/1            → count=2, avg=51, passRate=50%, 5 段分布
概览  GET  /api/stats/overview           → 4 用户 / 2 课程 / 16 题 / 2 考试 / 2 答卷
```

结论：七步闭环（建课 → 题库 → 组卷 → 发布 → 答题 → 阅卷 → 统计）在内存模式下可完整跑通，接口字段与前端调用一致。

## 7. 经验与教训

1. **契约先行是并行开发的前提**：BE 与 FE 全程零口头沟通，仅凭 `API契约.md` + 基线第 5 节对齐，36 个函数与 36 条路由一次对齐。
2. **可测试性设计降低验证成本**：`createApp(deps)` 工厂 + 内存仓储，使 217 条用例在 65 秒内跑完且不依赖数据库；注入时钟使「超时交卷」可确定性断言（并因此发现 D-01）。
3. **文档与代码必须双向核对**：BE 的 README 写「119 条用例」、写「submitted_at 记触发时刻」均已过期，若不核对会直接污染论文数据。
4. **产物需要机器校验**：mermaid 用 mermaid-cli 实跑、JSON 示例用 `JSON.parse`、DDL 用 node-sql-parser、docx/pptx 用 python-docx/python-pptx + Office 导出逐页目检，才发现了图题重复、表头不跨页、封面字体、pptx 的浮点 EMU 导致 PowerPoint 打不开等只有渲染才暴露的问题。
5. **AI 团队需要「人类做终审」**：角色会自我美化（如声称已压测），所有对外数字最终以真实执行输出为准。
