# 在线考试系统 · 前端实现说明

> 代码根目录：`code/web`　｜　基线依据：`00-team/project-brief.md` 第 5、6 节　｜　设计依据：`02-design/系统设计说明书.md` 第 3 节
>
> 本文说明前端代码的真实结构、路由与页面组成、组件契约、状态管理与接口映射，用于毕业论文第 5 章「系统实现」的前端部分。文中代码片段摘自 `code/web/src` 下的实际文件，未作改写（仅省略少量上下文）。

## 1 技术栈、构建配置与目录结构

### 1.1 技术栈与依赖

前端是纯单页应用（SPA），不引入任何 UI 组件库与 CSS 框架，所有控件与样式自建。依赖版本严格取自 `code/web/package.json`：

| 类别 | 包 | 版本 | 用途 |
|---|---|---|---|
| 视图库 | react | `~18.3.1` | 函数组件、Hooks、Context |
| 视图库 | react-dom | `~18.3.1` | `createRoot` 挂载、`StrictMode` |
| 路由 | react-router-dom | `~6.26.2` | `BrowserRouter`、`Routes`、`NavLink`、`useSearchParams` |
| HTTP | axios | `~1.7.9` | 实例、拦截器、超时与错误归一 |
| 构建 | vite | `~5.4.11`（devDependencies） | 开发服务器与生产构建 |
| 构建插件 | @vitejs/plugin-react | `~4.3.4`（devDependencies） | JSX 转换与 React Fast Refresh |

`package.json` 声明 `"type": "module"`，源码全部使用 ESM `import/export`。脚本只有三个：

| 命令 | 实际执行 | 说明 |
|---|---|---|
| `npm run dev` | `vite` | 启动 5173 开发服务器，`/api` 代理到后端 |
| `npm run build` | `vite build` | 生产构建，产物写入 `dist/` |
| `npm run preview` | `vite preview` | 本地预览 `dist/` 产物 |

需要说明：前端没有配置测试框架（无 jest/vitest）、没有 ESLint/Prettier 配置，样式为手写的单一 `src/styles.css`（约 2971 行，按模块分区注释）。这是「不引入 UI 库、样式集中管理」这一约束的直接结果，也构成第 10 节的一条限制。

### 1.2 构建配置与代理

`vite.config.js` 只做三件事：启用 React 插件、固定开发端口并配置代理、指定构建输出目录：

| 配置项 | 值 | 说明 |
|---|---|---|
| `plugins` | `[react()]` | JSX 编译与 HMR |
| `server.port` | `5173` | 开发端口 |
| `server.strictPort` | `true` | 端口被占用时直接报错，而不是静默换端口，避免代理与文档地址不一致 |
| `server.proxy['/api'].target` | `http://localhost:3000` | 与后端 `PORT` 默认值一致 |
| `server.proxy['/api'].changeOrigin` | `true` | 修改 Host 头，避免后端校验来源时被拒 |
| `build.outDir` | `dist` | 生产产物目录 |
| `build.sourcemap` | `false` | 不输出 sourcemap，减小产物体积 |

代理是前后端分离的关键：前端代码里所有请求都写成相对路径 `/api/xxx`（axios 的 `baseURL` 也是 `/api`），开发期由 Vite 转发到 3000 端口，因此**前端源码中不出现后端主机名与端口**；生产部署时只需由 Nginx 把 `/api` 反向代理到后端即可，无需改代码。

## 2 路由表

路由集中定义在 `App.jsx`，采用「嵌套路由 + 两级守卫」结构：外层 `RequireAuth` 包住 `Layout`，内层每条业务路由再包一层 `RequireRole`。完整路由共 16 条：

| 路径 | 组件文件 | 访问角色 | 说明 |
|---|---|---|---|
| `/login` | `pages/LoginPage.jsx` | 公开 | 登录页；`booting` 时显示全屏加载，已登录访问会被 `Navigate` 重定向到角色首页 |
| `/403` | `pages/ForbiddenPage.jsx` | 公开 | 无权限提示页，`RequireRole` 判定角色不符时跳转至此，可「返回首页」或「切换账号」 |
| `/admin/overview` | `pages/admin/OverviewPage.jsx` | admin | 全局概览：用户/教师/学生/课程/题目/考试/答卷七项计数与两张柱状图 |
| `/admin/users` | `pages/admin/UsersPage.jsx` | admin | 用户管理：分页列表、角色筛选、关键字搜索、新增/编辑/重置密码/禁用/删除 |
| `/admin/courses` | `pages/admin/CoursesPage.jsx` | admin | 课程管理：列表、前端关键字过滤、新增/编辑（可选任课教师）、删除 |
| `/teacher/questions` | `pages/teacher/QuestionsPage.jsx` | teacher、admin | 题库管理：课程/题型/难度/关键字筛选 + 分页、新增/编辑题目、JSON 批量导入 |
| `/teacher/exams` | `pages/teacher/ExamsPage.jsx` | teacher、admin | 考试管理：状态与课程筛选、发布、删除、覆盖式指派考生 |
| `/teacher/exams/new` | `pages/teacher/ExamFormPage.jsx` | teacher、admin | 新建考试并组卷；**编辑复用同一路由**，通过 `?id=<examId>` 进入编辑模式 |
| `/teacher/grading` | `pages/teacher/GradingPage.jsx` | teacher、admin | 阅卷中心：待阅答卷列表（可按考试过滤）+ 阅卷弹窗 |
| `/teacher/stats` | `pages/teacher/StatsPage.jsx` | teacher、admin | 成绩统计：场次摘要、五段分布、逐题正确率；支持 `?examId=` 直达某场次 |
| `/student/exams` | `pages/student/MyExamsPage.jsx` | student | 我的考试：被指派且已发布的考试卡片，按答卷状态与时间窗决定按钮 |
| `/student/exam/:examId` | `pages/student/ExamPage.jsx` | student | 在线答题：开考确认、答题卡、倒计时、自动保存、交卷 |
| `/student/result/:attemptId` | `pages/student/ResultPage.jsx` | student | 成绩与解析：得分概览 + 逐题对错、正确答案、评语、解析 |
| `/student/scores` | `pages/student/ScoresPage.jsx` | student | 我的成绩：历次已交卷成绩与平均分 |
| `/` | `App.jsx` 内 `RoleHome` | 已登录（否则跳登录） | 按角色重定向：admin → `/admin/overview`，teacher → `/teacher/exams`，student → `/student/exams` |
| `*` | `pages/NotFoundPage.jsx` | 公开 | 404 兜底页 |

三点实现细节：

1. **admin 可进入教师页**。`App.jsx` 中定义了 `const TEACHING_ROLES = ['teacher', 'admin'];`，注释写明「管理员具备教学管理权限（基线第 3 节），因此 /teacher/* 页面同时放行 admin」。这是前端唯一一处「跨角色复用页面」的放行。
2. **守卫逻辑不写在页面里**。`RequireAuth` 在 `booting` 为真时渲染全屏 `<Loading full text="正在校验登录状态…" />`，未登录时以 `redirect` 参数跳转登录页；`RequireRole` 在角色不符时统一 `<Navigate to="/403" replace />`，因此页面组件内不需要重复做「有没有权限」的判断。
3. **登录后回跳**。`RequireAuth` 把当前 `pathname + search` 编码进 `/login?redirect=...`，登录页的 `safeRedirect` 只接受以单个 `/` 开头、且不等于 `/login` 的地址（拒绝 `//evil.com` 这类协议相对 URL），校验通过才回跳，否则落到角色首页。

## 3 页面清单

### 3.1 公共页面

**登录页（`LoginPage`）** 采用左右分栏：左侧是品牌介绍、四条能力说明与三个演示账号卡片，右侧是用户名/密码表单。演示账号卡片点击后只做表单填充，不走任何假登录逻辑，提交仍调用真实 `POST /auth/login`。登录失败时错误信息内联显示在表单上方（该请求设置了 `skipErrorToast`，避免与页面内提示重复）。登录成功后写入令牌、弹出欢迎提示，并按 `redirect` 或角色首页跳转。

**403 页（`ForbiddenPage`）** 展示「无权限访问」说明与两个动作：返回首页（按当前角色计算 `homePath`）、切换账号（调用 `logout` 清令牌后跳登录页）。**404 页（`NotFoundPage`）** 只提供一个「返回系统入口」链接。

### 3.2 管理员页面

**全局概览（`OverviewPage`）** 调用 `getOverview()` 取七项计数，渲染成七张统计卡（用户总数、教师、学生、课程、题目、考试、答卷），并用两个纯 CSS 柱状图呈现「用户构成」与「资源规模」。页面底部用说明框标注数据来源与统计口径（答卷数含进行中、待阅卷与已评分）。加载失败时用 `EmptyState` 提供「重新加载」按钮，而不是白屏。

**用户管理（`UsersPage`）** 是列表 + 三个弹窗的典型 CRUD 页：表格列为用户名、真实姓名、角色、邮箱、状态、创建时间、操作；顶部提供角色下拉与关键字搜索，分页交给 `DataTable`。`CreateUserModal`、`EditUserModal`、`ResetPasswordModal` 分别对应 `createUser`、`updateUser`、`updateUser(id, { password })`。禁用/启用与删除都经 `useConfirm` 二次确认，且对「当前登录账号」禁用删除与禁用按钮（按钮 `title` 给出原因），防止管理员把自己锁在系统外。列表请求用 `seqRef` 递增序号丢弃过期响应，避免快速翻页时旧数据覆盖新数据。

**课程管理（`CoursesPage`）** 展示课程名称（含简介副行）、课程代码徽标、任课教师、创建时间。它同时调用 `listCourses()` 与 `listUsers({ role: 'teacher', page: 1, pageSize: 100 })` 来填充「任课教师」下拉，因此依赖管理员权限。搜索在前端对「名称 + 代码 + 教师名」做包含匹配，不额外请求后端；删除确认文案明确提示「课程下仍有题目或考试时服务端会拒绝删除」，与后端 40901 的行为对齐。

### 3.3 教师页面

**题库管理（`QuestionsPage`）** 顶部是课程、题型、难度、关键字四个筛选条件与搜索/重置按钮，主体是分页表格（题干 + 知识点 + 选项数量、题型徽标、星级难度、建议分值）。新增与编辑复用 `QuestionFormModal`；「批量导入」打开独立弹窗，用户粘贴题目 JSON，前端先做 `JSON.parse`、数组/`questions` 数组结构判断、1~500 条数量校验，再调用 `importQuestions`，成功后展示「成功 N 道 / 失败 M 道」及逐条失败原因（序号从 1 开始展示，后端 `index` 从 0 开始）。

**考试管理（`ExamsPage`）** 顶部按状态与课程筛选，表格展示考试名称（课程名副行）、状态徽标、时间窗、时长、总分/及格线、题目数与操作列。操作按状态分化：草稿显示编辑、指派、发布、删除；已发布显示指派、统计；已关闭只显示统计。发布与删除都经二次确认，删除文案提示「仅草稿且无答卷可删」。指派由 `AssignModal` 完成，弹窗顶部用警示条说明「覆盖式指派」：管理员可直接搜索学生并勾选（`listUsers({ role: 'student', pageSize: 100 })`），教师因 `/users` 仅管理员可调用，改为手工录入学生 ID（支持逗号、空格、顿号、分号分隔并用 chip 展示），提交后由后端校验每个 ID 是否为存在的学生。

**组卷页（`ExamFormPage`）** 是前端最复杂的表单页，分三块：基本信息（标题、课程、时长、开始/结束时间、及格线、乱序开关、说明）、左侧「从题库选题」（带题型/难度/关键字筛选与分页的表格，勾选加入试卷）、右侧「已选题目」（逐题可改分值、上移/下移、移除，并实时显示题目数量与试卷总分）。数据来源为 `listCourses()`、`listQuestions({ courseId, type, difficulty, keyword, page, pageSize })`、编辑时再加 `getExam(id)`。关键交互：切换课程会清空已选题目并弹确认；编辑模式下课程下拉禁用（后端也不允许换课程）；提交前做完整前端校验（标题长度、时间先后、时长 1~600、及格线不大于总分、至少 1 题、每题分值 > 0），校验通过后调用 `createExam` 或 `updateExam`。时间字段以 `datetime-local` 呈现，提交前经 `fromDatetimeLocal` 转成契约要求的 `YYYY-MM-DD HH:mm:ss`。

**阅卷中心（`GradingPage`）** 页面主体是待阅答卷表格（学生、考试、交卷时间、待评简答题数、操作），顶部可按考试过滤。点击「开始阅卷」后加载 `getGradingDetail(attemptId)`，以 `xl` 尺寸弹窗展示：顶部六项摘要（状态、交卷时间、客观分、主观分、当前总分、待评简答数），中部逐题展示题干、选项对比（`AnswerOptions` 标出学生作答与正确答案），客观题只读并提示「已自动判分」，简答题给出学生作答与参考答案对比以及得分输入框、评语输入框。提交前校验得分为 0~该题满分、最多两位小数，提交调用 `submitGrading(attemptId, items)`，成功后 toast 显示重算后的总分并刷新待阅列表。

**成绩统计（`StatsPage`）** 顶部下拉选择考试场次（默认选第一个有答卷的场次，支持 `?examId=` 直达），下方依次是五张统计卡（参考人数、平均分、最高分、最低分、及格率）、分数段分布（5 条 `ScoreBar`，按百分制折算）、数据说明列表、逐题正确率表（`ScoreBar` 按 60%/30% 分档着色）、以及底部「各场次统计摘要」表。数据来自 `listExamStats()` 与 `getExamStats(examId)`；当某场次 `count === 0` 时给出「暂无已交卷答卷，以下统计均为 0」的提示，而不是让五张卡显示 0 让人误解。

### 3.4 学生页面

**我的考试（`MyExamsPage`）** 以卡片网格展示被指派且已发布的考试，每张卡显示标题、答卷状态徽标、课程、时间窗、时长、总分/及格线、我的得分；进行中的卡片额外显示「剩余时间」。按钮由状态与时间窗共同决定：`in_progress` → 「继续答题」，`submitted`/`graded` → 「查看成绩」，未到开始时间 → 禁用「未到开考时间」，已过结束时间 → 禁用「考试已结束」，其余 → 「开始考试」。数据来自 `listAvailableExams()`，页面底部提示「答卷以服务端截止时间为准，超时将自动交卷」。

**在线答题（`ExamPage`）** 是全系统交互最密集的页面，分四个阶段：`loading`、`ready`（开考确认）、`active`（答题）、`error`。进入时先 `getPaper(examId)`：若试卷已带 `attempt` 且非进行中，直接 `replace` 跳成绩页；若带进行中的答卷，再 `getAttempt(attemptId)` 恢复已保存答案与剩余时间；否则展示开考确认页（时长、总分、及格线、题数、时间窗 + 「开始后计时不可暂停」警示），点击「开始考试」调用 `startAttempt(examId)` 后再取一次 `getAttempt`。

答题阶段四个关键行为：

- **倒计时以服务端为准**。前端不用本地「开考时刻 + 时长」推算，而是把服务端下发的 `remainingSeconds` 换算成本地截止时间戳：`setDeadline(Date.now() + remainingSeconds * 1000)`，同时保留服务端的 `deadlineAt` 文本用于展示。这样即使客户端时钟与服务器有偏差，倒计时起点也是服务端给的剩余量。
- **防抖自动保存**。每次选择/输入只更新内存答案并标记 dirty，400 ms 内的连续操作被合并为一次 `PUT /attempts/:id/answers`；保存状态在「保存中…/✓ 已保存 hh:mm:ss/保存失败，点击重试/答案将自动保存」四态间切换。
- **串行化与失败重试**。同一时刻只允许一个保存在飞（`inflightRef`），期间新产生的 dirty 记到 `pendingFlushRef`，待当前批次完成后再触发一轮；保存失败的题目会被重新放回 dirty 集合，并在循环中最多重试 20 轮，避免网络抖动导致答案丢失。
- **交卷确认与超时处理**。点「交卷」先弹 `ConfirmDialog`，展示总题数、已答数、未答数并声明「交卷后不能修改答案」。确认后 `doSubmit(false)` 先补存所有 dirty 题目（单题失败不阻塞交卷，服务端以已保存答案判分），再 `submitAttempt`，成功后带 `state` 跳成绩页。倒计时归零时 `Countdown` 触发 `onExpire` → `doSubmit(true)`，以「自动交卷」文案提示；若交卷返回 40901（例如服务端已判定超时），直接跳成绩页而不是报错。

**成绩与解析（`ResultPage`）** 调用 `getResult(attemptId)`，顶部是分数 hero（大字总分、满分、是否及格与及格线）与状态/客观分/主观分/开考时间/交卷时间；若状态为 `submitted`，额外提示「主观题待阅卷，当前总分为客观题得分」。下方逐题展示题型徽标、本题得分/满分、答对/答错或「人工评分」标记、题干、选项对比、简答的「我的作答 vs 参考答案」、教师评语与解析。从交卷跳转过来时读取 `location.state`，显示「交卷成功」或「考试时间已到，系统已自动交卷」以及待阅简答数量。

**我的成绩（`ScoresPage`）** 调用 `getStudentStats(user.id)`，上部两张统计卡（已交卷考试数、平均分），下部表格列出考试、交卷时间、得分/满分、及格线、结果（及格/未及格/待阅卷）、状态与「查看解析」链接，默认按交卷时间倒序。

## 5 状态管理

前端没有引入 Redux/MobX，状态分三层：全局登录态用 Context，服务端数据用「页面内 `useState` + `useEffect` 拉取」，跨组件的轻量通知用事件总线。

### 5.1 AuthContext：登录态与恢复机制

`AuthContext` 暴露 `user`、`booting`、`login`、`logout`、`hasRole` 五个值。恢复逻辑在挂载时执行一次：

```jsx
  useEffect(() => {
    let alive = true;
    const token = getToken();
    if (!token) {
      setBooting(false);
      return () => {
        alive = false;
      };
    }
    getMe({ skipErrorToast: true, skipAuthRedirect: true })
      .then((profile) => {
        if (alive) setUser(profile);
      })
      .catch(() => {
        clearToken();
        if (alive) setUser(null);
      })
      .finally(() => {
        if (alive) setBooting(false);
      });
    return () => {
      alive = false;
    };
  }, []);
```

要点有四：其一，本地有令牌不代表登录有效，必须用 `GET /auth/me` 向服务端确认（后端每次请求都会回查用户状态，因此被禁用/删除的账号立即失效）；其二，恢复期间 `booting` 为真，所有守卫渲染加载态，避免「先闪一下登录页再跳回首页」；其三，该请求带 `skipErrorToast` 与 `skipAuthRedirect`，令牌失效时不弹红色提示、也不整页跳转，而是静默清除令牌交给路由守卫处理；其四，用 `alive` 标记防止组件卸载后 `setState`。`login()` 同样以 `skipErrorToast` 调用登录接口，失败信息由登录页内联展示，成功后 `setToken` + `setUser`。

### 5.2 api/client.js：拦截器

axios 实例为 `baseURL: '/api'`、`timeout: 15000`、默认 JSON 头。请求拦截器从 `authStorage` 取令牌并注入 `Authorization: Bearer <token>`。

响应拦截器承担四件事：解包 `{code, message, data}`、把业务失败转成 `ApiError`、401 统一跳登录、非 401 错误统一 toast：

```js
client.interceptors.response.use(
  (response) => {
    const body = response.data;
    if (!body || typeof body.code === 'undefined') return body;
    if (body.code !== 0) {
      const error = new ApiError(body.code, body.message, response.status);
      handleError(error, response.config);
      throw error;
    }
    return body.data;
  },
```

因此业务代码拿到的直接是 `data` 本身（例如 `const list = await listExams()` 拿到数组），不需要层层 `.data.data`。HTTP 层错误（4xx/5xx）在第二个回调里归一：优先采用响应体的 `code/message`，无响应体则用 `请求失败（HTTP xxx）`，`ECONNABORTED` 提示「请求超时，请稍后重试」，其余提示「网络异常」。401 处理为 `clearToken()` + `window.location.assign('/login?redirect=...')`（已在登录页则跳过，避免循环），并支持 `skipAuthRedirect`、`skipErrorToast` 两个逐请求开关。

### 5.3 令牌存储

令牌存放在 `localStorage`，键名集中在 `api/authStorage.js` 的 `TOKEN_KEY = 'exam_system_token'`，读写用 `try/catch` 包裹以兼容隐私模式下 `localStorage` 不可用的情形。选择 localStorage 而非内存变量的原因是刷新页面后仍能恢复会话；代价是存在 XSS 读取风险，缓解手段是 React 默认转义、不渲染任何 `dangerouslySetInnerHTML`，以及令牌 8 小时过期。

## 7 关键代码片段

### 7.1 自动保存的防抖与串行化

`ExamPage` 的答案变更入口只做三件事：更新内存、标记 dirty、重置 400 ms 定时器；真正发请求的是 `flushSave`：

```jsx
  const handleAnswerChange = (questionId, value) => {
    if (submittingRef.current) return;
    const next = { ...answersRef.current, [questionId]: value };
    answersRef.current = next;
    setAnswers(next);
    dirtyRef.current.add(questionId);
    setSaveStatus('saving');
    window.clearTimeout(saveTimerRef.current);
    // 防抖 400ms：连续输入只触发一次保存，切题时定时器仍会执行
    saveTimerRef.current = window.setTimeout(() => {
      flushSaveRef.current?.();
    }, 400);
  };
```

`answers` 的 state 与 `answersRef` 双写是必要的：`setState` 是异步的，若 `flushSave` 只读 state，可能在一次连续输入中读到旧值；用 ref 保存最新值，定时器回调里读到的就是用户最后一次操作的结果。`flushSave` 内部再处理「一批脏题目 → 逐题 PUT → 若期间又变脏则继续下一轮」的循环，并用 `inflightRef`/`pendingFlushRef` 保证同一时刻只有一个保存在飞。

### 7.2 倒计时以服务端 deadline 为准

`Countdown` 本身不感知秒数来源，只接收一个本地时间戳并按 500 ms 重算；关键在于调用方如何构造这个时间戳——用服务端下发的 `remainingSeconds` 反推，而不是用本地开考时间加时长：

```jsx
      setDeadline(Date.now() + Math.max(0, Number(data.remainingSeconds) || 0) * 1000);
      setDeadlineLabel(data.deadlineAt || '');
```

组件侧的到期回调做了去重，保证整场考试只触发一次自动交卷：

```jsx
  useEffect(() => {
    expiredRef.current = false;
    const tick = () => {
      const value = calcRemaining();
      setRemaining(value);
      if (value <= 0 && !expiredRef.current) {
        expiredRef.current = true;
        callbackRef.current?.();
      }
    };
    tick();
    const timer = window.setInterval(tick, 500);
    return () => window.clearInterval(timer);
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [deadline]);
```

`onExpire` 被放进 `callbackRef` 而不是写进依赖数组，是为了避免父组件每次渲染生成新函数导致定时器被反复重建；`expiredRef` 在 `deadline` 变化时重置，适应「断线恢复后重新拿到剩余时间」的场景。即便前端定时器因休眠而延后，服务端在 `GET /attempts/:id` 与保存答案时都会做超时判定，时间权威始终在后端。

### 7.3 交卷前的补存与 409 处理

交卷不是简单调一个接口：先把所有 dirty 题目补存一遍，再提交，并对「已超时被服务端先判」的情况做兜底：

```jsx
      try {
        const pendingIds = Array.from(dirtyRef.current);
        dirtyRef.current.clear();
        for (const questionId of pendingIds) {
          try {
            await saveAnswer(attemptIdRef.current, {
              questionId,
              answer: serializeAnswer(questionId, answersRef.current[questionId])
            });
          } catch (err) {
            // 交卷前补存失败不阻塞交卷，服务端以已保存答案判分
          }
        }
        const result = await submitAttempt(attemptIdRef.current);
        setNotice('');
        navigate(`/student/result/${attemptIdRef.current}`, {
          replace: true,
          state: { justSubmitted: true, autoSubmitted: Boolean(auto), summary: result }
        });
      } catch (err) {
        submittingRef.current = false;
        setSubmitting(false);
        setAutoSubmitting(false);
        if (err.code === 40901) {
          navigate(`/student/result/${attemptIdRef.current}`, { replace: true });
          return;
        }
```

补存失败被刻意吞掉：交卷才是学生最关心的动作，个别题目的补存失败不应导致交卷失败，后端会用数据库中已保存的答案判分；而 40901 说明服务端认为该答卷已不能作答（已交卷或已超时自动交卷），此时跳成绩页比报错更符合用户预期。

## 8 样式与交互约定

**配色**。全局样式以 CSS 变量集中在 `:root`，主色 `#2563eb`（`--primary`，深色态 `#1d4ed8`，浅底 `#eff6ff`），页面底色 `#f5f7fb`、卡片白底、正文 `#1f2937`、次要文字 `#64748b`、边框 `#e5e7eb`；语义色为成功 `#16a34a`、危险 `#dc2626`、警告 `#d97706`，另加紫色 `#7c3aed` 与青色 `#0d9488` 用于状态徽标区分。圆角 `--radius: 12px`、`--radius-sm: 8px`，阴影两级（`--shadow-sm`、`--shadow`）。所有颜色通过变量引用，未在组件内写死色值。

**布局**。整体是「顶栏 + 左侧栏 + 主内容」的经典后台骨架：顶栏固定品牌与用户区，侧栏按角色渲染菜单分组（管理员两组、教师一组、学生一组），主内容用 `.page` + `.card` 组织，表单用 `.form-grid`、列表用 `.table-wrap`、统计用 `.stat-grid`。考试页是唯一的双栏布局（左侧题目与翻页，右侧答题卡），窄屏时答题卡上移到题目之前。

**响应式断点**。样式表末尾有三个断点：`1180px` 以下收窄组卷页右栏（340px）并把五列统计卡降为三列；`1023px` 以下侧栏改为横向滚动条、双栏网格全部堆叠、答题卡与成绩 hero 改为纵向；`640px` 以下顶栏换行、表单栅格单列、工具栏输入框占满整行、统计卡两列、答题卡网格降为 6 列。整体按「≥1024px 为主，窄屏可用」设计，不追求手机端完整适配。

**三态约定**。加载态统一用 `Loading`（表格内用 `DataTable` 的 `loading` 占位行），空态统一用 `EmptyState` 并尽量给出「下一步该做什么」的文案与按钮（如「去组卷」「去参加考试」），错误态分两种：页面级请求失败在卡片内用 `EmptyState` + 「重新加载」按钮，表单级失败在表单顶部用 `.alert-error` 展示后端 `message`。提示语统一由 `utils/toast` 弹出，成功提示约 2.6 s、错误约 4.2 s，与拦截器的自动提示共用同一容器，避免出现两套提示样式。

**交互细节**。所有危险操作（删除、发布、禁用、清空名单、退出登录、切换课程）都走 `ConfirmDialog` 二次确认，`danger` 操作确认按钮为红色；表单错误就地显示在字段下方，不弹窗；列表操作后优先局部刷新（`reloadKey` 自增）而不是整页刷新；分页控件同时提供页码与每页条数；表格中的长文本用 `title` 属性提供完整内容。

## 9 运行与构建

前置条件是后端已在 `http://localhost:3000` 运行（推荐 `npm run start:memory`）。

```bash
cd code/web
npm install
npm run dev       # 开发：http://localhost:5173，/api 代理到 3000
npm run build     # 生产构建，产物在 code/web/dist
npm run preview   # 本地预览 dist（默认 4173 端口）
```

开发期直接访问 `http://localhost:5173`，所有 `/api/*` 请求由 Vite 代理转发，浏览器地址栏不出现 3000 端口，因此不存在跨域 Cookie/来源问题（后端也开了 `cors()` 作为双保险）。构建产物为 `dist/index.html` 与 `dist/assets/*`（JS/CSS 带内容哈希），部署时把 `dist` 交给静态服务器，并把 `/api` 反向代理到后端即可；由于使用 `BrowserRouter`（HTML5 History 模式），静态服务器需配置「未命中文件时回退到 `index.html`」，否则刷新 `/student/exams` 这类深链接会 404。

## 10 已知限制与改进方向

1. **编辑路由语义不直观**。考试编辑复用了 `/teacher/exams/new?id=<examId>`，靠查询参数区分新建与编辑，缺少独立的 `/teacher/exams/:id/edit`。改进方向：拆出独立路由并在 `ExamFormPage` 内用 `useParams` 取值，同时保留对旧链接的兼容重定向。
2. **教师端指派考生需手输学生 ID**。因为基线规定 `GET /users` 仅管理员可调用，教师无法拉取学生名单，`AssignModal` 对教师退化为「输入 ID + chip 展示」。改进方向：为教师增加一个受限的学生检索接口（只返回本人课程相关的学生姓名与 ID），或由管理员批量导入选课名单。
3. **乱序开关只透传不生效**。`ExamFormPage` 提供「打乱题目顺序」开关并提交 `shuffle`，`paper` 接口也会返回该字段，但后端未按答卷种子乱序发卷，前端自然无从体现。改进方向：后端实现按 `attemptId` 固定种子的洗牌，前端无需改动。
4. **缺少前端自动化测试与静态检查**。`package.json` 只有 dev/build/preview 三个脚本，没有单测、组件测试与 ESLint，回归依赖人工点击。改进方向：引入 Vitest + React Testing Library 覆盖「自动保存防抖」「倒计时到期」「守卫跳转」等关键逻辑，并接入 ESLint。
5. **无代码分割，首屏加载全部页面**。所有页面在 `App.jsx` 中静态 import，构建为单一 JS 包，随页面增多体积会持续增长。改进方向：用 `React.lazy` + `Suspense` 按角色或路由拆分 chunk。
6. **倒计时仍受客户端时钟与休眠影响**。虽然起点取自服务端 `remainingSeconds`，但页面长时间后台挂起后 `setInterval` 会被节流，显示值可能滞后；真正的判定在后端，因此不会影响成绩，只是显示不够实时。改进方向：监听 `visibilitychange`，页面回到前台时重新拉取 `GET /attempts/:id` 校准剩余时间。
7. **401 处理使用整页跳转**。拦截器里用 `window.location.assign` 跳登录，会丢失 SPA 的过渡体验并触发整包重新加载。改进方向：改为由 Context 暴露的 `logout()` + 路由 `navigate`，或用自定义事件通知根组件。
8. **表单校验规则与后端重复，存在漂移风险**。前端为体验做了标题长度、时间先后、及格线 ≤ 总分、得分区间等校验，规则是手抄后端的一份副本；后端规则调整时前端可能滞后。改进方向：把校验规则与错误文案抽成共享常量（或在构建期从后端 schema 生成），后端仍是最终权威。
9. **无障碍与国际化未覆盖**。部分自定义控件（答题选项按钮、答题卡）依赖视觉状态而非完整 ARIA 语义，界面文案全部硬编码中文，未做 i18n。改进方向：补齐 `aria-pressed`/`aria-label`，把文案抽到字典文件。
